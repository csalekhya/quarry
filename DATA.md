# Data

quarry downloads nothing and commits no third-party data. Every dataset is
either generated by code in this repository or written by hand.

| Dataset | Where | Source | License | Size |
|---|---|---|---|---|
| TPC-H-like tables (region, nation, supplier, customer, part, partsupp, orders, lineitem) | generated at run time by `src/tpch.rs` (`quarry gen`, tests, benchmark) | synthetic, deterministic (SplitMix64 with fixed seeds) | MIT (this repo) | SF 0.01 ≈ 60k lineitem rows; SF 0.1 ≈ 600k; written under `data/` (git-ignored) |
| `fixtures/employees.csv`, `fixtures/departments.csv` | committed | written by hand for the demo and CSV tests; names are generic first names | MIT (this repo) | < 1 KB |
| Feature/fuzz tables `t`, `u`, `e` | generated inside `tests/common/features.rs` | synthetic, deterministic, about 15% NULLs per column | MIT (this repo) | 300 / 100 / 0 rows |

## About the TPC-H-like data

The generator follows the TPC-H schema, per-scale-factor table sizes, key
relationships (every lineitem's part/supplier pair exists in partsupp, a third
of customers never order) and value domains (segments, priorities, ship modes,
part types, containers, nation and region names). It is **not** the official
TPC `dbgen`:

- comments are 2-7 words from a small vocabulary instead of the grammar-based
  text generator;
- the partsupp supplier formula is simplified (see `DECISIONS.md`);
- decimals are stored as `DOUBLE`;
- orders get 1-7 lines with uniform quantities, so the Q18 threshold is lowered.

Results and timings are therefore not comparable to published TPC-H results,
and nothing here is a TPC Benchmark. "TPC-H" names the query and schema shapes
the workload imitates.

Parquet output clusters `lineitem` by `l_shipdate` and `orders` by
`o_orderdate` (16,384-row row groups by default) so date filters can skip row
groups. CSV output keeps generation order.

Regenerate any scale factor with:

```sh
cargo run --release -- gen --sf 0.1 --out data/sf0.1 --format parquet
```
